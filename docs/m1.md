# M1 — hot-strategy and an honest worldline

`soft/arena/m1_smoke.aura`. Seed `20261005`. M0 is unchanged: it does not
load this path and still races heavy vs light without `hot-strategy`.

## What M1 guarantees

1. `ar:law` is a real `std/hot-strategy` slot. Seed is `set-code` plus
   `hot-strategy:register!`. A later body goes in with `hot-strategy:swap!`.
   `hot-strategy:heal!` restores the pre-swap snapshot. This is not a
   renamed `set!`. The body is `(lambda () (list g bn bd fric))`.
2. The slot can change **mid-run**. Ten ticks run on the seed light pack.
   A `set!` body is gate-rejected and the tick stays 10. A bouncy body is
   swapped in (`SWAP name=ar:law tick=10`). Five more ticks run on that
   body (`tick=15`). An ugly body that returns a short list fails the pack
   probe, `heal!` runs, and tick is still 15. Prior ticks are not retconned.
3. Heal restores the last good snapshot, which is the bouncy body, not the
   original light seed. `(ar:law)` is `(1 3 4 0)` after that heal.
4. At live tick 8 the world prints `MUTATE tick=8 fric-boost=1` and raises
   `*fric-boost*`. That is a Soft mutation log, not `mutate:rebind`.
5. The dual race is still `rules-heavy` vs `rules-light` on the same seed,
   separate from the hot-slot demo. `KEEP` / `DROP` use the greater score.
   This seed keeps light.
6. `fiber_live` is printed only when that race spawned two distinct
   positive fiber ids and both `fiber:join`s returned a number, and
   `fiber:spawn-backend` is > 0. Otherwise the same two thunks run on the
   host and the line is `host-sequential`. A missed join is not labeled
   `fiber_live`.

## Measured on this tip

`bash scripts/smoke_m1.sh` against `/workspace/aura-grok/build/aura`:

| line | value |
|------|--------|
| `MUTATE` | `tick=8 fric-boost=1 slot=ar:law` |
| `SWAP` | `name=ar:law tick=10 reason=mid-swap` |
| `HEAL` | `name=ar:law tick=15 reason=probe` |
| `RACE` | `heavy=8000423 light=35000528` |
| `WORLD` | `line=fiber_live backend=2 joins=2/2` |
| `KEEP` | `mid=2 reason=longer-survival-stamp` |
| `DROP` | `mid=1 reason=shorter-survival-rollback` |
| end | `ARENA_M1_OK` |

`backend=2` is the CLI thread fallback (`fiber:spawn-backend`), not the
serve-async scheduler (`backend=1`). Joins landed and the scores match the
M0 tape, so the stamp is `fiber_live`. If a future binary returns `#f`
from spawn or join, this smoke still passes with `host-sequential` and
must not say `fiber_live`.

## 中文

M1 在第 10 拍 `hot-strategy:swap!` 换物理规则包，第 15 拍用
`hot-strategy:heal!` 拉回上一份好快照。tick 不被 swap 清掉。第 8 拍印
`MUTATE tick=8 fric-boost=1`。`rules-heavy` 对 `rules-light` 的双世界线：
这次二进制上两条 fiber 都 join 成功，所以印
`fiber_live backend=2 joins=2/2`。backend 2 是 CLI 线程回退，不是
serve-async。没 join 就不印 `fiber_live`。M0 仍然不加载本文件。
